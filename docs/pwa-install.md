# PWA install + verification (kid-quest)

kid-quest is a mobile-first installable web app. On iOS the demo target is
"Add to Home Screen" from Safari, which gives a standalone (no browser chrome)
launch experience that visually matches a native app. This doc covers the
install steps, what to verify after install, and the runbook expectations for
the on-call / hot-spare device during a demo.

## iPhone install (Safari, iOS 16+)

1. Open Safari on the iPhone (Chrome and Firefox on iOS do **not** support
   home-screen install of third-party PWAs — it must be Safari).
2. Navigate to the deployed URL (e.g. `https://kid-quest.vercel.app/`).
3. Tap the **Share** button (square with up-arrow) in the bottom toolbar.
4. Scroll down and tap **Add to Home Screen**.
5. Confirm the name "kid-quest" and tap **Add** (top-right).
6. The icon appears on the home screen. Tap to launch.

After install, the app launches in **standalone mode**: no Safari address bar,
no tab bar. The status bar uses the default iOS style (`statusBarStyle: "default"`
in `app/layout.tsx`).

## Android install (Chrome)

1. Open Chrome on Android, navigate to the deployed URL.
2. Tap the three-dot menu, then **Install app** (or **Add to Home screen**).
3. Confirm and launch.

Chrome on Android will surface a native install prompt automatically once it
detects the manifest + service worker. We do not currently render a custom
install banner; rely on the browser UI.

## Verifying a successful install

After tapping the home-screen icon:

- [ ] App opens **without** Safari/Chrome browser chrome (no URL bar, no tabs).
      This confirms `display: "standalone"` is being honored.
- [ ] The viewport is portrait and locked (`orientation: "portrait"` in the
      manifest). Rotating the device should not flip the layout.
- [ ] The app loads on a cold launch even with the device on a flaky network
      (precached static assets render the shell). Note: API responses are
      **not** cached — see "Cache scope" below.
- [ ] Hitting `/api/health` (via in-app behavior or a manual fetch from
      another tab in the same install) returns a live response, never a
      stale cached one.

## Cache scope (what Serwist caches, what it doesn't)

The service worker is generated by [Serwist](https://serwist.pages.dev/) from
`app/sw.ts`. Configuration:

- **Precache** — All Next.js build output (`_next/static/*`, the app shell,
  manifest, icons) is injected via `__SW_MANIFEST` at build time and served
  cache-first on revisit. This is what makes cold launch fast and what makes
  the app render at all when offline.
- **Runtime cache (`defaultCache`)** — Standard Serwist patterns for Google
  Fonts, same-origin images, scripts, and HTML pages. See
  `@serwist/next/worker` for the exact policy list.
- **`/api/*` → `NetworkOnly` (explicit override)** — Every request whose
  pathname starts with `/api/` is served `NetworkOnly`. This applies to both
  GET and POST. **Rationale:** the parent-facing classifier log, the kid
  session events, and demo telemetry must always reflect the live backend.
  A stale classifier verdict cached in the SW would be worse than a network
  failure — it would silently mislead the parent watching the log.

Practical implication: if the device is offline, `/api/*` calls **will fail**.
That is the intended behavior. The kid-flow UI should surface a friendly
"check your connection" state (owned by the kid surface), not a stale answer.

## Refresh + update behavior

- `reloadOnOnline: true` (in `next.config.ts`) — when the browser regains
  connectivity, Serwist triggers a full reload so the user picks up any
  freshly deployed shell.
- `skipWaiting: true` + `clientsClaim: true` (in `app/sw.ts`) — a new SW
  build takes control of all open tabs on first install. There is no
  "two-tab stale UI" trap during a demo.
- Hard cache-bust if needed: from the device, delete the home-screen icon,
  Safari → Settings → Clear History and Website Data, then re-install.

## Hot-spare prep (for runbook agent)

For live demos, prep at least one spare iPhone with the app already
installed. Checklist:

1. **Battery** ≥ 80%. Disable Low Power Mode (it can throttle JS).
2. **Brightness** at the venue level (auto-brightness off if possible).
3. **Wi-Fi** joined to the venue network and tested (open the app, run one
   classifier round-trip, confirm a fresh API response).
4. **Airplane test** — toggle airplane mode on, relaunch from home screen,
   confirm the shell loads from precache. Toggle airplane mode off, confirm
   a subsequent `/api/*` call succeeds (proves the SW is not over-caching).
5. **Standalone launch** — always launch from the home-screen icon during
   the demo, never from Safari. Standalone mode hides browser chrome and
   gives the right photo for stakeholders.
6. **Service worker version** — if a fresh deploy went out, force-reload
   once (pull-to-refresh in standalone) so the new SW activates before
   the demo starts.

## Troubleshooting

| Symptom                                  | Likely cause / fix                                                                 |
| ---------------------------------------- | ---------------------------------------------------------------------------------- |
| Icon installs but launches into Safari   | Manifest `display` not loaded. Hard reload the site in Safari, re-add to home.     |
| Stale verdict shown in parent log        | `/api/*` should be `NetworkOnly`. Confirm `app/sw.ts` ships the override.          |
| "No internet" error in standalone        | Expected if offline — `/api/*` does not have an offline fallback in v1.            |
| Old shell after deploy                   | Reload once; `reloadOnOnline` + `skipWaiting` should pick up the new SW.           |
| Icon is blank / black square             | iOS could not fetch `/apple-touch-icon.png`. Confirm it 200s in DevTools.          |

## Files

- `public/manifest.webmanifest` — manifest served at `/manifest.webmanifest`.
- `public/icon-192.png`, `public/icon-512.png` — manifest icons.
- `public/apple-touch-icon.png` — iOS home-screen icon (180x180 conventionally;
  the placeholder shipped here is 1x1 and will be replaced before launch).
- `app/sw.ts` — service worker source. Generates `public/sw.js` at build time.
- `next.config.ts` — wraps Next config with `withSerwistInit`.
- `app/layout.tsx` — `metadata.manifest`, `metadata.appleWebApp`,
  `metadata.icons` for the install hints.
